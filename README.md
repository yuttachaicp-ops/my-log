# My Log

แอปบันทึกรายรับ–รายจ่ายส่วนตัว สร้างจาก UI ต้นแบบในโฟลเดอร์ `My_Log_UI_for_Cowork`

## เปิดใช้งาน

```bash
npm install
npm run dev      # เปิด http://localhost:5173
```

คำสั่งอื่น

```bash
npm run build    # ตรวจชนิดข้อมูลด้วย tsc แล้ว build ลง dist/
npm run preview  # ดูผล build
npm test         # รันเทสต์ทั้งหมด
```

ต้องใช้ Node 18 ขึ้นไป (เครื่องที่ทดสอบใช้ Node 22)

## สิ่งที่ทำได้ตอนนี้

- หน้าภาพรวม: ยอดคงเหลือ รายรับ รายจ่าย เทียบกับเดือนก่อน กราฟรายวัน โดนัทรายหมวด รายการล่าสุด งบประมาณ เป้าหมายเงินออม
- รายการทั้งหมด: ค้นหา กรองตามประเภท/หมวดหมู่/เดือน สลับดูทุกเดือน แบ่งหน้าเมื่อเกิน 20 รายการ
- เพิ่ม แก้ไข ลบรายการ พร้อม validation และกล่องยืนยันก่อนลบ
- หมวดหมู่: เพิ่ม แก้ ลบ ตั้งไอคอน สี และงบต่อเดือน
- งบประมาณและเป้าหมายเงินออม: แถบความคืบหน้า เตือนสีเหลืองเมื่อใช้เกิน 80% และสีแดงเมื่อเกินงบ
- ตั้งค่า: ยอดยกมาต้นงวด สลับแหล่งข้อมูล ส่งออกข้อมูลเป็น JSON
- รองรับทั้ง desktop (sidebar) และ mobile (แถบล่าง + ปุ่มลอย)
- สถานะ loading / empty / error / success ครบ ข้อความภาษาไทยทั้งหมด

## ข้อมูลเก็บที่ไหน

ตอนนี้เก็บใน localStorage ของเบราว์เซอร์ ยังไม่ได้ต่อ backend จริง

มีสองก้อนแยกกันเด็ดขาด

| โหมด | storage key | ใช้ทำอะไร |
|---|---|---|
| ข้อมูลของฉัน | `mylog.real.v1` | ข้อมูลจริงของผู้ใช้ เริ่มต้นว่างเปล่า |
| ข้อมูลตัวอย่าง | `mylog.sample.v1` | ตัวเลขสมมติไว้ดูหน้าตา ทุกรายการมี `source: 'sample'` |

สลับโหมดได้ที่หน้าตั้งค่า ค่าเริ่มต้นคือโหมดจริง เขียนฝั่งหนึ่งไม่กระทบอีกฝั่ง
และเมื่ออยู่โหมดตัวอย่างจะมีแถบเหลืองเตือนบนทุกหน้า

## ติดตั้งลงมือถือ

แอปเป็น PWA ติดตั้งลงจอโฮมได้เหมือนแอปทั่วไป แต่ต้องเอาขึ้นออนไลน์ด้วย https ก่อน
เบราว์เซอร์จะไม่ยอมให้ติดตั้งจาก `localhost:5173` หรือจาก IP ในวง LAN

### 1. build

```bash
npm run build      # ได้ไฟล์ทั้งหมดในโฟลเดอร์ dist/
```

### 2. เอา `dist/` ขึ้นออนไลน์

**วิธีที่ตั้งค่าไว้ให้แล้ว: GitHub Pages ผ่าน git push**
ดูขั้นตอนตั้งค่าครั้งแรกใน `SETUP-GITHUB-PAGES.md`
ตั้งเสร็จแล้วการอัปเดตเหลือแค่ `git add . && git commit -m "..." && git push`
GitHub Actions จะรันเทสต์ build และ deploy ให้เอง (ดู `.github/workflows/deploy.yml`)

วิธีอื่นถ้าอยากทำมือ:

**Netlify Drop** — ง่ายที่สุด ไม่ต้องสมัครก็ได้

1. เข้า https://app.netlify.com/drop
2. ลากโฟลเดอร์ `dist` ไปวาง
3. ได้ลิงก์ https มาทันที

**GitHub Pages** — เหมาะถ้าอยากเก็บโค้ดไว้ด้วย

1. push โปรเจกต์ขึ้น repo
2. push เนื้อใน `dist/` ไปที่ branch `gh-pages` หรือโฟลเดอร์ `docs/`
3. Settings → Pages → เลือก branch นั้น

`base` ใน `vite.config.ts` ตั้งเป็น `'./'` ไว้แล้ว จึงใช้ได้ทั้งที่รากโดเมนและในโฟลเดอร์ย่อย
ไม่ต้องแก้ config ตอนเปลี่ยนที่โฮสต์

ทุกครั้งที่แก้โค้ด ต้อง `npm run build` แล้วอัปโหลด `dist/` ใหม่

### แจ้งเตือนเวอร์ชันใหม่

เมื่ออัปโหลด `dist/` ชุดใหม่ขึ้นไป ผู้ใช้ที่เปิดแอปอยู่จะเห็นแถบ "มีเวอร์ชันใหม่พร้อมใช้งาน"
พร้อมปุ่มอัปเดตที่ด้านล่างจอ กดแล้วแอปโหลดใหม่ทันที ข้อมูลใน localStorage ไม่หาย

กลไก — เบราว์เซอร์ดูว่ามีเวอร์ชันใหม่จากการเทียบไฟล์ `sw.js` แบบไบต์ต่อไบต์
ถ้าไฟล์เหมือนเดิมเป๊ะจะไม่ถือว่ามีอัปเดต แม้โค้ดส่วนอื่นเปลี่ยนไปแล้ว
`vite.config.ts` จึงมี plugin `stamp-service-worker` คอยประทับรหัส build ลงใน `dist/sw.js`
ทุกครั้งที่ build (เห็นได้จากบรรทัด `stamp-service-worker: sw.js build = ...` ตอน build)
**ไม่ต้องขยับเลขเวอร์ชันเองใน `sw.js`**

`sw.js` ตั้งใจไม่เรียก `skipWaiting()` ตอนติดตั้ง เวอร์ชันใหม่จึงค้างสถานะ waiting
รอจนผู้ใช้กดปุ่มเอง จะได้ไม่ถูกตัดกลางคันตอนกำลังกรอกฟอร์ม

แอปตรวจหาอัปเดตให้เองตอนสลับกลับมาเปิดแอป และทุก 30 นาทีระหว่างเปิดค้าง
กด "ไว้ก่อน" แล้วจะเงียบไป 2 ชั่วโมง ส่วนหน้าตั้งค่ามีปุ่มตรวจเองและบอกเลขเวอร์ชันที่ใช้อยู่

### 3. ติดตั้งบนเครื่อง

**Android (Chrome)** — เปิดลิงก์ → เมนูสามจุด → ติดตั้งแอป / เพิ่มลงในหน้าจอหลัก

**iPhone** — ต้องเปิดด้วย **Safari** เท่านั้น (Chrome บน iOS ทำไม่ได้)
ปุ่มแชร์ → เพิ่มไปยังหน้าจอโฮม

เปิดจากไอคอนบนจอโฮมจะได้หน้าจอเต็ม ไม่มีแถบเบราว์เซอร์
กดค้างที่ไอคอนบน Android จะมีทางลัด "เพิ่มรายการ" ให้กดเข้าฟอร์มได้เลย

### ข้อควรรู้เรื่องข้อมูล

ข้อมูลเก็บใน localStorage ของเบราว์เซอร์แต่ละเครื่อง **ไม่ได้ซิงก์ข้ามเครื่อง**

- ติดตั้งบนมือถือจะได้แอปเปล่า ไม่มีข้อมูลที่บันทึกไว้บนคอม
- ย้ายข้อมูลได้ด้วยการส่งออก JSON จากหน้าตั้งค่าบนเครื่องหนึ่ง แล้วนำเข้าอีกเครื่อง
  (ปุ่ม "นำเข้าจากไฟล์ JSON" ในหน้าตั้งค่า — การนำเข้าจะแทนที่ข้อมูลเดิมทั้งหมด มีกล่องยืนยันก่อน)
- ล้างข้อมูลเว็บไซต์ในเบราว์เซอร์ = ข้อมูลหาย ควรส่งออกเก็บไว้เป็นระยะ

การซิงก์ข้ามเครื่องจริง ๆ ต้องรอตอนต่อ backend ซึ่งยังทำไม่ได้ (ดูหัวข้อท้ายไฟล์)

## กฎการคำนวณที่ใช้อยู่

- ยอดคงเหลือ = ยอดยกมาต้นงวด + รายรับสะสม − รายจ่ายสะสม จนถึงสิ้นเดือนที่เลือก
- ยอดสุทธิของเดือน = รายรับเดือนนั้น − รายจ่ายเดือนนั้น
- เทียบกับเดือนก่อน ถ้าเดือนก่อนเป็นศูนย์จะแสดงขีด ไม่ใช่ 0% หรือ ∞
- เงินทุกก้อนปัดสองตำแหน่งทีละขั้น ไม่ให้เศษ floating point สะสม

กฎเหล่านี้ยังไม่ได้ยืนยันกับ schema ของระบบเดิม ถ้าระบบเดิมใช้สูตรอื่นต้องปรับที่ `src/lib/calc.ts`

## ยังไม่ได้ทำ

- **ยังไม่ได้ต่อกับ Google Sheet / LINE Bot เดิม** — `appsScriptSource.ts` เป็นโครงเปล่า
  ยังเติม mapping ไม่ได้เพราะยังไม่ได้เห็นซอร์ส Apps Script และ schema ของชีต
- ยังไม่มีระบบบัญชีหลายบัญชีและการโอนระหว่างบัญชี
- ยังไม่มีรายงานรายเดือนแบบส่งออก PDF
- ยังไม่มีเทสต์ระดับ component (ตอนนี้ครอบการคำนวณและชั้นข้อมูล)

## ถ้าจะต่อกับระบบเดิม

ต้องมี 3 อย่างก่อน

1. ซอร์ส Apps Script ของบอท (`Code.gs`) เพื่อดูว่า endpoint รับอะไรและตอบอะไร
2. โครงชีต — ชื่อแท็บ หัวคอลัมน์ และชนิดข้อมูลในแต่ละคอลัมน์
3. ยืนยันกฎธุรกิจ โดยเฉพาะสูตรยอดคงเหลือ และวิธีกันรายการซ้ำระหว่าง UI กับ LINE

จากนั้นเติม `rowToTransaction` / `transactionToRow` ใน `appsScriptSource.ts`
แล้วเพิ่มโหมดใหม่ใน `data/index.ts` — ส่วน UI ไม่ต้องแก้เลย

ฟังก์ชัน `isDuplicate()` ใน `calc.ts` เตรียมไว้แล้วสำหรับกันรายการซ้ำ
โดยดูจาก `externalId` + `source` ก่อน ถ้าไม่มีจึงเทียบวันที่ ประเภท ยอด และชื่อ

ห้ามใส่ key หรือ URL จริงลงในซอร์ส ให้ผู้ใช้กรอกในหน้าตั้งค่าแล้วเก็บใน localStorage
